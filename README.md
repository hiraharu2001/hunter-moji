# hunter-moji

かな（ひらがな・カタカナ）とハンター文字を相互に変換する静的 Web アプリ。ブラウザだけで動き、スマートフォンでもそのまま使える。変換したハンター文字は透かし入りの画像としてコピーできる。字形は [日本テレビ公式サイトの用語解説にあるハンター文字表](https://www.ntv.co.jp/hunterhunter/dictionary/index.html)を正本として作画し（[omniglot の対応表](https://www.omniglot.com/images/writing/hunter.gif)とも一致する）、清音 46 字・長音・記号を SVG パスとして持つ。

公開サイト: [https://hiraharu2001.github.io/hunter-moji/](https://hiraharu2001.github.io/hunter-moji/)

## 使い方

画面上部のタブで 3 つの画面を切り替える。タブは URL の hash（`#/to-hunter`、`#/to-kana`、`#/chart`）に対応するため、リロードしても表示は変わらない。

### かな → ハンター文字

テキストエリアにひらがな・カタカナを入力すると、その場でハンター文字になる。横書きで表示し、枠の幅で折り返す。

`画像をコピー` は変換結果を PNG にしてクリップボードへ入れる。チャットや SNS へそのまま貼り付けられる。画像のコピーに対応していないブラウザでは、代わりに PNG を保存する。`画像を保存` はいつでも PNG を保存する。`共有` は端末の共有シートを使えるときだけ表示し、画像を共有できない端末では共有リンクを渡す。書き出した画像には右下に出典 `hiraharu2001.github.io/hunter-moji` を薄く入れる。画面に表示しているハンター文字には入れない。

`リンクをコピー` は入力した本文を載せた共有リンク（`#/to-hunter?t=<本文>`）を作る。開いた人には同じ変換結果が出る。URL が長くなりすぎないよう、本文が 200 字を超えるときは作れない。

クリップボードと共有シートのブラウザ API は HTTPS（と localhost）でしか使えない。http で開いたときは `共有` を出さず、HTTPS で開くよう促す一文を画面に出す。

### ハンター文字 → かな

五十音順のパレットからハンター文字を選んで入力し、読みを表示する。読みは `ひらがな` / `カタカナ` の切り替えで表示を変えられ、`よみをコピー` で表示中のよみをクリップボードへ入れる。`濁点`、`半濁点`、`小書き` は直前の 1 字に付け外しする切り替えで、付けられない字を選んでいるときは押せない。`1 字削除` と `全消去` で入力を戻す。

### 五十音対応表

清音・濁音・半濁音・小書き・記号のすべてについて、ひらがなと字形の対応を一覧する。

## 対応する文字

清音 46 字、濁音・半濁音、小書き（ぁぃぅぇぉゃゅょっゎ）、長音「ー」、句読点「、」「。」、疑問符「？」と感嘆符「！」、区切り記号「×」を変換する。半角の `?` と `!` は全角へそろえてから変換する。半角スペースは 1 マス分の空き、改行は行送りとして扱う。

対応表には清音・濁音・半濁音・小書き・長音に加えて「？」「！」もあり、この 2 字は対応表と同じ通常の疑問符・感嘆符の形で描く。「、」「。」「×」の字形だけが対応表に無いため、線の太さと大きさをそろえた独自定義とする。

カタカナ（全角・半角とも）はひらがなへ読み替えたうえで同じ字形に変換する。ヵ・ヶ は対応する小書きのひらがなを扱っていないため、通常の か・け として変換する。

漢字・英数字などの未対応文字は変換せず、警告色のまま結果に残したうえで「ひらがな・カタカナに直してください」という警告を出す。

## 開発

Node 22 と pnpm 10 が前提。pnpm を個別に入れていない場合は、以下のコマンドを `corepack pnpm ...` として実行する。

```sh
pnpm install
pnpm dev
```

| コマンド | 内容 |
| --- | --- |
| `pnpm dev` | 開発サーバーを起動する |
| `pnpm build` | 型検査（`tsc -b`）と本番ビルドを実行する |
| `pnpm preview` | ビルド結果をローカルで確認する |
| `pnpm lint` | Biome で lint と書式を検査する |
| `pnpm format` | Biome で lint と書式を自動修正する |
| `pnpm test` | Vitest でユニットテストを実行する |

変換ロジックは `src/lib/` にある純粋関数に閉じている。正規化とトークン化は `convert.ts`、パレット入力の編集操作は `compose.ts`、折り返しの座標計算は `layout.ts`、書き出す画像の組み立ては `export.ts`、共有リンクの読み書きは `share.ts` が担い、いずれも `*.test.ts` で検証する。クリップボードと共有シートのブラウザ API は `clipboard.ts` にまとめ、ここだけテストの対象外とする。どの操作を画面に出すかの判定は `capabilities.ts` の純粋関数に置く。

## 字形を差し替える

字形の正本は `src/glyphs/glyphs.ts` で、1 文字ごとに `{ char, paths, dots? }` の形で持つ。`paths` は線で描く SVG パス、`dots` は塗りつぶしの円で、い段の黒丸のように線では描けない部分に使う。

```ts
{ char: "き", paths: ["M26 14 L26 82"], dots: [{ cx: 45, cy: 48, r: 16 }] },
```

差し替えるときの決まりは次の 4 点。

- 座標系は `viewBox="0 0 100 100"` に固定する。
- 基字は x が 12〜78、y が 12〜84 の範囲に収める。線の色と太さは描画側が `currentColor` と一定の太さで与える。
- 塗りつぶしは `dots` の円だけに限る。`paths` は線として描かれる。
- 濁点・半濁点は基字に含めず、`dakutenGlyph` と `handakutenGlyph` を右下（x が 78〜100、y が 74〜96）に重ねて合成する。この範囲には基字を置かない。

小書きは基字と同じ字形を 0.62 倍に縮小して右下へ寄せて描くため、専用のデータは要らない。`src/glyphs/glyphs.test.ts` が「対応表の全文字に字形がある」「字形が互いに重複しない」「座標が viewBox の内側に収まる」を検査するので、差し替え後は `pnpm test` を実行する。

## デプロイ

GitHub Pages で配信する。`main` への push で `.github/workflows/deploy.yml` が動き、lint → test → build の順に検査したうえで `dist` を Pages へデプロイする。

公開 URL は `https://<user>.github.io/hunter-moji/` で、このパスは `vite.config.ts` の `base` と対応する。リポジトリ名を変えるときは `base` も合わせて変える。
