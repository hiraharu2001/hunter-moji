# hunter-moji

ひらがなとハンター文字を相互に変換する静的 Web アプリ。ブラウザだけで動き、変換したハンター文字は SVG と PNG で保存できる。字形は原作を参照していない独自の近似デザインで、清音 46 字と長音・句読点を自作の SVG パスとして持つ。

## 使い方

画面上部のタブで 3 つの画面を切り替える。タブは URL の hash（`#/to-hunter`、`#/to-kana`、`#/chart`）に対応するため、リロードしても表示は変わらない。

### ひらがな → ハンター文字

テキストエリアにひらがなを入力すると、その場でハンター文字になる。横書きで表示し、枠の幅で折り返す。`SVG で保存` と `PNG で保存` を押すと、表示中の変換結果をそのまま画像として書き出す。

### ハンター文字 → ひらがな

五十音順のパレットからハンター文字を選んで入力し、読みをひらがなで表示する。`濁点`、`半濁点`、`小書き` は直前の 1 字に付け外しする切り替えで、付けられない字を選んでいるときは押せない。`1 字削除` と `全消去` で入力を戻す。

### 五十音対応表

清音・濁音・半濁音・小書き・記号のすべてについて、ひらがなと字形の対応を一覧する。

## 対応する文字

清音 46 字、濁音・半濁音、小書き（ぁぃぅぇぉゃゅょっゎ）、長音「ー」、句読点「、」「。」を変換する。半角スペースは 1 マス分の空き、改行は行送りとして扱う。

漢字・カタカナ・英数字などの未対応文字は変換せず、警告色のまま結果に残したうえで「ひらがなに直してください」という警告を出す。

## 開発

Node 22 と pnpm 10 が前提。pnpm を個別に入れていない場合は、以下のコマンドを `corepack pnpm ...` として実行する。

```sh
pnpm install
pnpm dev
```

| コマンド | 内容 |
| --- | --- |
| `pnpm dev` | 開発サーバーを起動する |
| `pnpm build` | 型検査（`tsc -b`）と本番ビルドを実行する |
| `pnpm preview` | ビルド結果をローカルで確認する |
| `pnpm lint` | Biome で lint と書式を検査する |
| `pnpm format` | Biome で lint と書式を自動修正する |
| `pnpm test` | Vitest でユニットテストを実行する |

変換ロジックは `src/lib/` にある純粋関数に閉じている。正規化とトークン化は `convert.ts`、パレット入力の編集操作は `compose.ts`、折り返しの座標計算は `layout.ts` が担い、いずれも `*.test.ts` で検証する。

## 字形を差し替える

字形の正本は `src/glyphs/glyphs.ts` で、1 文字ごとに `{ char, paths }` の形で SVG パスを持つ。

```ts
{ char: "あ", paths: ["M22 38 A28 26 0 1 1 78 38 A28 26 0 1 1 22 38", "M30 84 L70 84"] },
```

差し替えるときの決まりは次の 3 点。

- 座標系は `viewBox="0 0 100 100"` に固定する。
- 塗りは使わず、線だけで描く。線の色と太さは描画側が `currentColor` で与える。
- 濁点・半濁点は基字に含めず、`dakutenGlyph` と `handakutenGlyph` を右上（x が 82〜98、y が 4〜20）に重ねて合成する。この範囲には基字を置かない。

小書きは基字と同じパスを 0.6 倍に縮小して描くため、専用のデータは要らない。`src/glyphs/glyphs.test.ts` が「対応表の全文字に字形がある」「字形が互いに重複しない」「座標が viewBox の内側に収まる」を検査するので、差し替え後は `pnpm test` を実行する。

## デプロイ

GitHub Pages で配信する。`main` への push で `.github/workflows/deploy.yml` が動き、lint → test → build の順に検査したうえで `dist` を Pages へデプロイする。

公開 URL は `https://<user>.github.io/hunter-moji/` で、このパスは `vite.config.ts` の `base` と対応する。リポジトリ名を変えるときは `base` も合わせて変える。
